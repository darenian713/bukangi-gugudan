# 금곡초 GRIP 구구단 – 부캉이의 부산 여행 (학교용)

> 학교 수업용 버전입니다. 학습자 단계는 **초등 저학년 · 초등 중학년 · 초등 고학년** 3단계만 있습니다.
> 첫 화면에서 **[혼자 하기]** 또는 **[👥 실시간 대결]**(교실 TV + 학생 태블릿, 9장)을 고를 수 있습니다.
> (부산교육 한마당용 5단계 버전은 `bukangi-gugudan` 폴더에 따로 있습니다.)

아기 상어 부캉이가 구구단 문제를 풀며 부산 명소 5곳(감천문화마을 → 자갈치시장 → 부산타워 → 광안대교 → 해운대)을 지나 바다로 돌아가는 터치형 구구단 게임입니다.
서버 없이 동작하는 정적 웹앱(HTML·CSS·JavaScript)입니다.

## 1. 바로 실행하기

- 폴더 안의 `index.html`을 크롬/엣지/사파리로 열면 바로 실행됩니다. (인터넷이 없으면 제목 글꼴만 기본 글꼴로 바뀝니다.)
- 태블릿·크롬북·전자칠판·PC 모두 지원: 화면 키패드 터치, 마우스, 키보드(숫자키·Backspace·Enter) 모두 됩니다.

## 3. 설정 바꾸기 (`js/config.js`)

메모장이나 VS Code로 `js/config.js`를 열어 숫자·글자만 바꾸고 저장 → 브라우저 새로고침.

| 바꾸고 싶은 것 | 위치 | 예 |
| --- | --- | --- |
| 학교 이름·프로그램 이름 | `schoolName`, `programName` | `'○○초등학교'`, `'GRIP'` |
| 단계별 출제 범위 | `levels`의 `minDan`~`maxDan`, `minMul`~`maxMul` | 2~9단, ×2~9 |
| 한 판 시간 | `levels`의 `time` (초) | `60` → `90` |
| 장소당 정답 수 | `levels`의 `perPlace` | `4` → `3` |
| 장소 이름·순서·아이콘 | `places` 배열 | `name`, `short`, `icon` |
| 점수 규칙 | `scoring` | 정답 10점, 콤보 5개마다 +5 … |
| 별 기준 | `stars` | 1곳 ★, 3곳 ★★, 5곳 ★★★ |
| 연출 시간 | `timing` | 오답 정답 보여 주기 0.7초 등 |

> 따옴표(`' '`)와 쉼표(`,`)를 지우지 않도록 주의하세요. 화면이 하얗게 나오면 마지막에 고친 줄의 따옴표·쉼표를 확인하세요.

장소 그림 종류(`scene`)는 `gamcheon`, `jagalchi`, `tower`, `gwangan`, `haeundae` 중에서 고를 수 있고, 목록에 없는 값이면 기본 하늘·언덕 그림이 나옵니다.

## 4. 이미지 바꾸기

- **부캉이 캐릭터**: 배경이 투명한 PNG를 `assets/bukangi.png` 이름으로 넣으면 자동으로 그 이미지가 쓰입니다. 파일이 없으면 코드로 그린 임시 아기 상어 부캉이가 나옵니다. (캐릭터 사용 권한을 꼭 확인하세요.)
- **장소 사진**: 선생님이 직접 찍은 사진을 `assets/stages/stage1.jpg` ~ `stage5.jpg`로 넣으면 그 장소 배경이 사진으로 바뀝니다. 파일이 없는 장소는 그림 배경 그대로입니다. 인터넷에서 받은 사진은 저작권 문제로 쓰지 마세요.

## 5. 최고 기록

- 단계별 최고 기록은 **그 기기의 그 브라우저**에만 저장됩니다(localStorage). 다른 기기와 공유되지 않고, 서버로 보내지 않습니다.
- 기록을 지우려면 브라우저 설정에서 해당 사이트 데이터를 삭제하세요.
- 결과 화면 아래 **GRIP 기록용 요약**(이름·단계·정답률·도달 장소·점수·날짜)은 `복사하기`를 누르거나 화면을 캡처해 그립카드에 옮겨 적으면 됩니다.

## 6. GitHub Pages로 배포하기 (학생은 링크·QR로 접속)

1. [github.com](https://github.com)에 로그인 → 오른쪽 위 **+** → **New repository**.
2. 저장소 이름 입력(예: `bukangi-gugudan`) → **Public** 선택 → **Create repository**.
3. 만들어진 저장소 화면에서 **uploading an existing file** 클릭 → 이 폴더 **안의 파일·폴더 전부**(`index.html`, `css`, `js`, `assets` …)를 끌어다 놓기 → **Commit changes**.
   - `index.html`이 저장소 맨 위(루트)에 있어야 합니다.
4. 저장소 **Settings → Pages** 메뉴로 이동.
5. **Build and deployment → Source**를 `Deploy from a branch`, **Branch**를 `main` / `/(root)`로 고르고 **Save**.
6. 1~2분 뒤 같은 화면 위쪽에 주소가 나옵니다: `https://<내아이디>.github.io/bukangi-gugudan/`
7. 나중에 `config.js`를 고치면 저장소에서 그 파일을 다시 올리기만 하면 몇 분 뒤 반영됩니다. (학생 기기는 새로고침)

**Netlify로 더 간단히**: [app.netlify.com/drop](https://app.netlify.com/drop)에 이 폴더를 통째로 끌어다 놓으면 바로 주소가 생깁니다(계정 로그인하면 계속 유지).

## 7. 접속용 QR 코드 만들기

- **크롬(PC)**: 게임 주소를 연 상태에서 주소창 오른쪽 **공유 아이콘 → QR 코드 만들기** → **다운로드**. 이미지를 TV·전자칠판에 띄우거나 인쇄합니다.
- **크롬(안드로이드/크롬북)**: 메뉴(⋮) → **공유** → **QR 코드**.
- **사파리(아이패드)**: 공유 버튼으로 주소를 복사한 뒤, 네이버 앱의 **QR 코드 만들기**나 학교에서 쓰는 QR 생성 서비스에 붙여 넣어 만들 수 있습니다.
- 학생 태블릿에서는 카메라 앱으로 QR을 비추면 바로 열립니다. **홈 화면에 추가**해 두면 다음부터 앱처럼 바로 실행됩니다.

## 9. 실시간 대결 (교실 TV + 학생 태블릿)

교실 TV(전자칠판)에 부산 지도를 띄우고, 학생들은 각자 태블릿으로 구구단을 풉니다. 정답 하나마다 내 부캉이가 한 칸 앞으로(틀리면 한 칸 뒤로) 가고, 가장 먼저 바다에 도착한 학생(개인전)이나 팀(팀전)이 이깁니다. 지도는 혼자 하기와 같은 명소 5곳(감천마을 → 자갈치 → 부산타워 → 광안대교 → 해운대 → 바다)과 그 장소 그림을 씁니다.

> 실시간 대결은 여러 기기가 연결돼야 해서 **인터넷 주소(GitHub Pages 등)에서만** 됩니다. `index.html`을 파일로 열면 혼자 하기만 됩니다.

### 9-1. Firebase 준비하기 (처음 한 번, 무료 Spark 요금제)

1. <https://console.firebase.google.com> → **프로젝트 추가**(예: `geumgok-gugudan`). Google 애널리틱스는 꺼도 됩니다.
2. **빌드 → Realtime Database → 데이터베이스 만들기** → 위치 **싱가포르(asia-southeast1)** → **잠금 모드로 시작**.
3. **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명 → 사용 설정 → 저장**.
4. **보안 규칙**: Realtime Database → **규칙** 탭 → 내용을 모두 지우고 `battle/database.rules.json` 내용을 붙여 넣기 → **게시**.
5. **연결 값**: 톱니바퀴 → **프로젝트 설정 → 일반 → 내 앱 → 웹(</>) 앱 추가** → 나오는 값 중 `apiKey`, `authDomain`, `databaseURL`, `projectId`, `appId` 5가지를 `js/firebase-config.js`에 붙여 넣기. (`databaseURL`이 안 보이면 Realtime Database 화면 위쪽 주소 `https://…firebasedatabase.app`)
6. **허용 도메인**: Authentication → **설정 → 승인된 도메인 → 도메인 추가** → `내아이디.github.io` 추가(GitHub Pages로 배포할 때).

이 값들은 공개돼도 괜찮은 값이에요. 실제 보호는 4번 보안 규칙이 합니다.

### 9-2. 배포

6장(GitHub Pages)과 똑같이 올리면 됩니다. `battle` 폴더와 `js/firebase-config.js`가 같이 올라가야 합니다(`dev` 폴더는 안 올려도 됨).

- TV: `https://<내아이디>.github.io/<저장소>/battle/host.html`
- 학생: TV 화면의 QR을 찍거나 `…/battle/join.html` (첫 화면 [실시간 대결] 버튼으로도 갈 수 있음)

### 9-3. 수업에서 쓰는 법

1. **TV**: [실시간 대결] → [선생님: 방 만들기] → 큰 **방 번호 4자리 + QR코드**.
2. **학생**: QR 또는 방 번호 → **별명(최대 6글자, 실명 아니어도 됨) + 비밀번호 숫자 4자리**.
3. TV 왼쪽에서 설정(개인전/팀전·팀 수, 출제 단, 도착까지 칸 수, 틀리면 한 칸 뒤로/2초 쉬기, 제한 시간, 끝나는 때, 중간 참여) → **[시작!]**
   - **끝나는 때**: **모두 도착 👏**(기본) / 3등까지 도착 / 1등 도착 즉시. '모두 도착'은 먼저 온 친구가 응원하며 기다리고, TV에 "바다 도착 12/20명"과 남은 친구 이름이 나오며, 마지막 친구가 도착하면 다 같이 박수 엔딩이 나와요. 와이파이가 끊겨 회색인 친구는 기다리지 않아요.
4. 3·2·1 → 학생마다 각자 다른 문제가 각자 속도로. TV 지도에서 부캉이가 움직이고, 오른쪽에 실시간 순위 5위까지.
5. 끝나면 1·2·3등 시상대 + 전체 순위표(도착 순서/이동 칸, 정답 수, 정답률). **[같은 방에서 다시 하기]** 또는 **[방 닫기]**(방 기록 모두 삭제, 24시간 지난 방은 자동 정리).

**선생님 관리**(대기 화면 이름표 옆, 게임 중엔 [학생 관리])

| 버튼 | 하는 일 |
| --- | --- |
| ✏️ 이름 바꾸기 | 부적절한 별명 바꾸기. 학생은 새 이름 + 원래 비밀번호로 다시 들어올 수 있음 |
| 🔑 비밀번호 초기화 | 같은 이름으로 새 비밀번호를 정해 들어오면 위치·점수·팀 그대로 |
| 🚪 내보내기 | 학생 기록 삭제, 학생 화면에 안내 |
| 팀 이름표 누르기 | (팀전 대기 화면) 다른 팀으로 옮기기. [🔀 다시 섞기]로 랜덤 재배정 |

**자주 생기는 일**

- *TV 브라우저를 닫았어요* → 같은 TV·같은 브라우저에서 `battle/host.html`을 열고 [이전 방 이어서 하기]. 게임이 그대로 이어집니다. (다른 컴퓨터에서는 이어서 진행할 수 없어요.)
- *학생이 새로고침했어요* → 같은 탭이면 바로 복귀, 다른 기기면 이름 + 비밀번호로 복귀.
- *와이파이가 끊긴 학생* → TV에서 회색, 다시 연결되면 원래 색.
- *비밀번호 5번 연속 틀림* → 그 기기에서 30초 대기.

### 9-4. 대결 설정 바꾸기 (`js/config.js`의 `battle`)

| 바꾸고 싶은 것 | 위치 | 지금 값 |
| --- | --- | --- |
| 처음 설정값 | `battle.defaults` | 개인전, 2~9단, 20칸, 한 칸 뒤로 + 2초 쉬기, 제한 시간 없음, **모두 도착하면 박수 엔딩** |
| 게임 중 새로 들어오기 | `battle.defaults.lateJoin` | `true`(허용: 출발점에서 시작, 팀전이면 인원이 가장 적은 팀) |
| 고를 수 있는 단 | `battle.danChoices` | 2~9단(고학년용으로 11~19단도 넣을 수 있음) |
| 팀 이름·색·그림 | `battle.teams` | 부캉이팀 / 온달이팀 / **동백팀 / 갈매기팀**(3·4번째 팀: 부산 시화·시조) |
| 학생 부캉이 색 | `battle.playerColors` | 24색 |
| 별명 길이, 비밀번호 잠금 | `battle.nameMax`, `pinFailLimit`, `pinLockSec` | 6글자, 5번, 30초 |

- 명소·학교 이름·부캉이 그림은 혼자 하기 설정(`places`, `schoolName`, `characterImage`)을 그대로 씁니다. `assets/stages/stage1.jpg`~를 넣으면 대결 지도 카드도 사진으로 바뀝니다.
- `assets/bukangi.png`를 넣으면 **부캉이팀 대표**가 그 그림으로 나옵니다. 학생 한 명 한 명은 색으로 구분해야 해서 그림 부캉이를 몸 색만 바꿔 씁니다.
- 온달이 그림은 아직 없어서 온달이팀은 주황색 부캉이로 나옵니다. 그림이 생기면 `assets/ondal.png`로 넣고 `teams`의 두 번째 줄을 `image: 'assets/ondal.png'`로 바꾸세요.

### 9-5. 알아 두기

- **팀 도착**: 팀 대표 위치 = 팀원 위치 평균이라, **팀원 모두가 바다에 가야** 팀이 도착합니다. 먼저 간 학생은 응원 화면을 봅니다. 자리를 오래 비운 학생은 [내보내기]하면 평균에서 빠지고, 제한 시간을 같이 쓰면 좋아요.
- 비밀번호는 원문을 저장하지 않고 `SHA-256(방번호+이름+비밀번호)`만 저장합니다. 실명·학생 명단을 미리 저장하지 않습니다.
- Spark 요금제 동시 접속은 100개: 한 반(20여 명 + TV)은 충분, 여러 반이 같은 프로젝트를 동시에 쓰면 넘을 수 있어요.

### 9-6. 개발·테스트 (`dev/`, 선생님은 몰라도 됨)

Node.js와 Java가 있으면 `dev` 폴더에서:

```
npm install
npm test                 # 심판 규칙 단위 테스트
npm run emulator         # (다른 창) Firebase 에뮬레이터 + 보안 규칙
npm run serve            # (다른 창) http://127.0.0.1:5050/
npm run test:rules && npm run test:e2e && npm run test:load
node tests/e2e-all.cjs    # '모두 도착' 엔딩
```

브라우저로 직접 해 보기: 에뮬레이터·serve를 켜고 `http://127.0.0.1:5050/battle/?emu=1` (`?emu=1` = 실제 Firebase 대신 에뮬레이터).
